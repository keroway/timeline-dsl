## 修正詳細

### PR #24 — eval_map_expr accessor バグ修正（Issue #20）

**問題**: `claim(P569).year` の `.year` 以外のアクセサ（`.month` 等）を指定した場合も `time_value_to_year` が実行されていた。アクセサの分岐が無効化されていた。

**修正**: `Some("year") | None` のみ `time_value_to_year` を呼び、それ以外は `None` を返すよう修正。

**品質評価**: 仕様に沿った最小限の修正。テストも追加済み。

---

### PR #25 — CLAUDE.md 更新（Issue #21）

**問題**: `CLAUDE.md` の「未実装」セクションに、すでに実装済みの機能（再インポートポリシー、import query、HTML レンダラ、lint）が残っていた。

**修正**: 実装済み機能を「実装済み」セクションに移動、CLI サブコマンド数を 4 → 12 に更新。

**品質評価**: ドキュメントと実装の整合性が回復した。

---

### PR #26 — dsl-spec.md 廃止済み `source` 削除（Issue #22）

**問題**: map ブロックの `source` プロパティは廃止済みにもかかわらず、`dsl-spec.md` の EBNF・コード例・プロパティ表に残存していた。また `merge_by_source` の説明が誤っていた。

**修正**: EBNF・コード例・テーブルから `source` を削除。`merge_by_source` の説明を正確な内容に修正。

**品質評価**: 仕様書が実装の source of truth として信頼できる状態になった。

---

### PR #27 + #32 — init テンプレート整理 + flaky test 修正（Issue #23, #29）

**問題 #23**: `render_init_tdsl` でエイリアスの自動生成ロジックと明示指定ロジックが混在し、可読性が低かった。

**問題 #29**: 並列テスト実行時に一時ファイル名（ナノ秒のみ）が衝突し、flaky test が発生していた。

**修正**: エイリアス生成を明示化・コメントで意図を明記。一時ファイル名にスレッドIDを追加して衝突回避。

**品質評価**: テスト安定性が向上。CI の信頼性が回復した。

---

### PR #33 — validate start>end チェック & SPARQL QID 抽出改善（Issue #30, #31）

**問題 #30**: `validate.rs` に `Span` / `EventRange` の start > end 検出がなかった。不正な年表定義がサイレントにスルーされていた。

**問題 #31**: SPARQL クエリ結果の QID 抽出が `row.into_values().next()` という順序依存実装だった。`?item` が最初のバインディングでない場合に誤った値を取得するリスクがあった。

**修正 #30**: `validate` ループで `start > end` を検出して警告を追加。

**修正 #31**: `?item` キーを優先取得し、存在しない場合は `wikidata.org/entity/Q*` URI をフォールバックとして使用。

**品質評価**: 両修正ともテストで動作を保証。SPARQL 改善は Wikidata の標準的なクエリ記法との整合性を高める。
