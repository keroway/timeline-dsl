# ADR 0004: PDF ページ分割戦略（テーブルのみを対象とする縮小スコープ）

- **Status**: Accepted
- **Date**: 2026-07-15
- **Deciders**: keroway
- **Related issues**: #617（本 ADR）, #609（親: paginated PDF export）, 実装先行 issue: #618（レイアウトエンジン）, #619（ヘッダ/フッタ/ページ番号）, #620（既存機能との整合）, #621（テスト戦略）, #622（docs）
- **Supersedes**: なし（ADR 0002「PDF出力方式の選定」を補完し、単一ページ前提だった D2 系の記述にページネーション機能を追加する）

## コンテキスト

現行の PDF 出力（ADR 0002）は `svg2pdf` + `pdf-writer` によるベクタPDFで、タイムライン本体と `--show-table` のテーブルを常に **1ページに縮小して収める**（`docs/dsl-spec.md:598`, `docs/cli-spec.md:404`）。項目数が多いタイムラインでは、印刷時にテーブル・チャートとも実用的な大きさを割れないという課題がある。

親issue #609 は当初、時間範囲・laneグループ・テーブル行・「タイムラインページ＋テーブルページ」構成のいずれで分割するかを未決として提示していたが、本 ADR ではスコープを絞り込んで決定する。

## 決めること（受け入れ条件からの引用）

- ページ分割の軸: 時間範囲 / lane グループ / テーブル行 / 「タイムラインページ＋テーブルページ」構成。
- CLI API: opt-in の `--pdf-pagination`（デフォルトは現行単一ページ）。
- 既存 `svg2pdf` / `pdf-writer` パイプライン、CJK、縦横向き、余白、用紙サイズ、全テーマとの互換性。
- ヘッダ/フッタ、ページ番号、タイトルメタデータ、テーブル見出しの繰り返し。
- `--show-table` / `--show-legend` / group band / gantt・zigzag / open-ended との整合。
- テスト戦略。

## 決定事項

### D1. スコープ縮小: 対象は「アイテムテーブルのページ分割」のみ。タイムライン本体（チャート部分）は現行どおり単一ページの縮小描画を維持する

- **時間範囲や lane グループでのタイムライン本体の分割は本 ADR のスコープ外**とする。理由:
  - チャート部分の分割は、ページ境界をまたぐバー（span/event_range）のクリッピング・視覚的連続性の保証・group band やレーンラベルの再描画など、レイアウトエンジンを実質的に新規設計する規模の作業になり、Effort/Risk（親issue: Effort L, Risk HIGH）に見合う十分な検証時間が現時点で確保できない。
  - 一方、**アイテムテーブルのページ分割**は行単位の素直な分割で実現でき、既存の「タイムラインを縮小して1ページに収める」というモデルと共存できる（テーブルの行数が多い場合の実用上のペインポイントに対して費用対効果が高い）。
- したがって、本 ADR が確定する `--pdf-pagination` は「**テーブルページを複数ページに分割する**」機能であり、「タイムラインチャートを複数ページに分割する」機能ではない。後者が将来必要になった場合は、本 ADR とは別に新しい ADR で再評価する（「未決定事項」参照）。

### D2. ページ構成: 「タイムラインページ（1枚、既存どおり）＋ テーブルページ（N枚、新規）」

- 1ページ目: 既存どおりタイムライン本体（`--show-table` 指定時も、テーブルは1ページ目には描画しない。`--pdf-pagination` 有効時はテーブルを別ページ群に切り出す）。
- 2ページ目以降: アイテムテーブルを用紙サイズ・余白に収まる行数ごとに分割して描画。テーブルの列構成・整形は既存 `--show-table` の実装をそのまま流用する。

### D3. CLI API: `--pdf-pagination`（bool フラグ、opt-in）

- `tdsl render --format pdf --show-table --pdf-pagination` のように指定する。
- **デフォルトは無効**（現行どおりテーブルも1ページに縮小して収める）。既存の `--format pdf` 単体・`--show-table` 単体の出力は本ADRにより一切変更しない（完全な後方互換）。
- `--pdf-pagination` は `--show-table` が指定されていない場合は無効（分割対象のテーブルが存在しないため）。`--show-table` なしで `--pdf-pagination` のみを指定した場合はエラーとする（silent no-op にしない。AGENTS.md §4.1）。

### D4. ヘッダ/フッタ・ページ番号・タイトルメタデータ・テーブル見出し

- 各テーブルページ共通のフッタに「ページ番号（`i / N`）」を描画する。
- 各テーブルページの先頭にテーブル見出し行（列名）を再描画する（1ページ目のみでなく全テーブルページで見出しが見える）。
- PDF メタデータのタイトル（既存 `PdfOptions.title` / `ir.meta.title` 補完ロジック、ADR 0002 補遺参照）は分割の有無に関わらず単一の PDF ドキュメントとして1つ設定する（タイムラインページ・テーブルページを問わず同一）。
- タイムラインページ（1ページ目）にはページ番号を付与しない（従来どおり単一チャートページの体裁を維持）か、あるいは「1 / N（Nはテーブルページ込みの総ページ数）」を全ページに付与するかは実装時に決定してよい細部とする（本ADRでは必須要件としない）。

### D5. 既存機能との整合

- `--show-legend` はタイムラインページ（1ページ目）にのみ描画する（現行どおり）。テーブルページには影響しない。
- group band / gantt / zigzag / open-ended range は、いずれもタイムライン本体（1ページ目）の描画に関わるものであり、D1 によりタイムライン本体はページ分割の対象外のため、**本ADRによる変更・相互作用は一切発生しない**。既存の単一ページ描画ロジックがそのまま使われる。
- 用紙サイズ・縦横向き・余白（`--pdf-size` / `--pdf-landscape` / `--pdf-margin`、ADR 0002 補遺）は、テーブルページにもタイムラインページと同一設定を適用する。

### D6. CJK・既存パイプラインとの互換性

- テーブルページの描画も既存の `svg2pdf` + `pdf-writer`（ADR 0002 D1/D2）パイプラインをそのまま使う。新規の変換方式は導入しない。
- CJK テキスト（レーンラベル・テーブルセル）のフォント読み込みは既存の `fontdb` システムフォント読み込みロジックを流用する。

### D7. テスト戦略

- ローカル外部ビューアに依存しない、決定的な構造検証を採用する:
  - **ページ数アサーション**: 生成PDFのページオブジェクト数が、テーブル行数・用紙サイズ・余白から計算される期待ページ数と一致すること。
  - **構造的アサーション**: 各ページに見出し行・ページ番号相当のテキストオブジェクトが存在すること（座標までは厳密に固定しないゴールデンではなく、存在検証中心とする。将来的にゴールデン画像比較が必要になった場合は別途検討）。
- CJK・縦横・用紙サイズの組み合わせマトリクスは、既存 `pdf::tests` の構成（ADR 0002 補遺）に倣って追加する。

## 比較した代替案

| 方式 | 判定 | 理由 |
|---|---|---|
| **テーブルのみページ分割（採用）** | ✅ 採用 | 既存の単一ページタイムライン描画と共存しやすく、実装・テストのブラスト半径が小さい。実用上のペインポイント（大きな項目テーブルが1ページに収まらず読めない）に直接対応する。 |
| 時間範囲でタイムライン本体を分割 | ❌ 不採用（本ADRの範囲外） | ページ境界をまたぐバーのクリッピング・継続性表示（例: 「...続く」マーカー）など新規のレイアウトエンジン設計が必要で、Effort/Riskに見合う検証時間が確保できていない。 |
| lane グループでタイムライン本体を分割 | ❌ 不採用（本ADRの範囲外） | 同上。加えてグループを跨ぐ相対関係（同時期の別laneイベント）が分断され、可読性がかえって下がる懸念がある。 |
| テーブル行 + 時間範囲の両方を初回スコープに含める | ❌ 不採用 | 親issueの Risk: HIGH という評価に対し、初回実装は最小の縮小スコープに留めるべきと判断（Q6 確認事項として合意）。 |

## 既知リスク

- テーブルのみを分割対象とすることで、当初issueが暗黙に期待していた「長いタイムライン本体の複数ページ化」というニーズには対応しない。将来的にそのニーズが顕在化した場合は、本ADRを supersede する新しいADRでタイムライン本体の分割方式を別途設計する必要がある。
- 1ページ目（タイムライン）とテーブルページのページ番号の連番の扱い（D4 で細部を実装時判断とした点）は、実装時にユーザー向けCLIヘルプ・ドキュメントで明確にする必要がある。

## 未決定事項（本 ADR の範囲外）

- タイムライン本体（チャート）自体の複数ページ化（時間範囲/laneグループでの分割）。将来必要になった時点で別ADRとして再評価する。
- ゴールデン画像比較によるPDF出力の視覚回帰テスト導入の是非。
- HTML/SVG/PNG出力へのページ分割相当機能の展開（現状PDF専用の課題として扱う）。
